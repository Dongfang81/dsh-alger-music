# Moony 系列 IP 与 DSH 安全接入设计

日期：2026-08-18

## 1. 背景

`dsh-moony-singer` 当前只有一只音乐宠物：歌手或唱片内容显示在圆脸中，蓝紫色圆耳随 DSH agent 状态变化，并通过歌词气泡说话。

此前的多宠物尝试仅替换了兔、猫、狐、犬等 CSS 耳型与颜色，缺少统一造型语法；同时，圆脸上的五官、月球纹理和媒体内容语义混杂，状态色又会覆盖角色本色。结果虽然“有多只宠物”，但不像一个可持续扩展的原创 IP 系列。

本设计建立 Moony 的固定母体、首发角色体系和安全接入边界。视觉升级不得改变 DSH 客户端插件的加载契约，也不得让单只角色错误阻断播放器或整个 DSH。

## 2. 目标

- 建立一套可长期扩展、具有统一辨识度的 Moony IP 规则。
- 保留“圆脸是媒体内容容器”的现有核心能力。
- 使用耳朵、可选尾巴、颜色信号与动作表达身份和情绪。
- 在 DSH 中提供 `Moony Classic` 加六只首发角色，共七个可选角色。
- 在 40px 和 64px 两种显示尺寸下保持轮廓清晰。
- 将角色数据、渲染、状态映射和故障回退分离，避免再次发生插件加载事故。

## 3. 非目标

- 本阶段不制作完整 3D 模型、宣传动画或实体潮玩工程文件。
- 本阶段不新增后端 API、音乐播放器协议或 DSH service 依赖。
- 本阶段不接入 DSH 设置页；角色选择器放在现有展开音乐浮窗中。
- 本阶段不修改 `apply(ctx)`、客户端 `inject`、侧边栏 slot 或模块加载方式。
- 本阶段不通过手动杀进程验证；只有离线检查全部通过后，才使用 DSH 现有受管方式加载新版。

## 4. 核心 IP 语法

### 4.1 圆脸

圆脸不是传统角色五官，而是 Moony 的“月面内容容器”。

- 空闲或没有媒体内容时，圆脸是完全无五官的空白软胶月面。
- 有歌手照片或唱片封面时，媒体内容占据完整圆面。
- 五官、陨石坑、Emoji、月牙符号不得叠加在照片或封面上。
- 图片不存在或加载失败时，回退为空白圆面，不显示 `🎵` 等占位 Emoji。
- 所有角色使用相同的圆脸尺寸、边框厚度、材质光影和媒体裁切规则。

设计原则：**脸承载内容，身体表达情绪。**

### 4.2 月化耳朵

耳朵来自可辨认的动物远亲轮廓，但必须经过统一的“月化”处理，不能直接复制兔耳、猫耳或犬耳。

所有角色耳朵共享：

- 相同的耳根连接方式。
- 相近的软胶厚度与双层轮廓。
- 统一的内层月纹结构。
- 独立的耳尖信号灯区域。

角色差异来自：

- 耳朵剪影、长度、朝向与对称关系。
- 固定的角色本色与辅色。
- 待机动作和听歌律动节奏。

角色本色始终保留。DSH 状态色只能进入耳尖灯和外轮廓光，不得替换整只耳朵的颜色。

### 4.3 尾巴

尾巴是可选身份结构，不是每只 Moony 的必备器官。

- 有尾角色使用尾巴补充情绪与节奏动作。
- 无尾角色依靠双耳角度、节奏和不对称动作表达。
- 尾巴不得遮挡圆脸媒体内容或扩大拖动命中区域。

### 4.4 材质

DSH 内采用 2.5D 软胶语言：圆润厚边、有限高光、单层体积阴影。实现仍使用 DOM、CSS 与内联 SVG 能力，以支持实时换脸和状态动画。

完整 3D 仅作为未来宣传图、动画与实体商品的延展方向，不进入本次实现。

## 5. 命名与系列结构

`Moony` 是所有角色的统一主名，个体使用英文人格副名，例如 `Moony · Echo`。

### 5.1 常驻初代

#### Moony Classic

- 定位：现有初代、经典版，同时指向古典音乐偏好。
- 说明：英文角色名使用 `Classic`；描述古典音乐曲风时使用规范表达 `classical music`。
- 造型：保留蓝紫色圆耳和初代身份，不纳入首发六只的“听音乐方式”席位。
- 尾巴：无。
- 默认选择：是。

### 5.2 首发六只

#### Moony · Pulse

- 听歌方式：节拍追逐者。
- 耳型：被节拍切开的双月瓣，前后弹跳。
- 本色：紫色系。
- 尾巴：无。

#### Moony · Echo

- 听歌方式：回忆共振者。
- 耳型：向后收拢的回声壳形。
- 本色：靛蓝与银蓝。
- 尾巴：环形尾，缓慢画圆。

#### Moony · Drift

- 听歌方式：沉浸漂流者。
- 耳型：自然下垂的长月耳。
- 本色：雾蓝与青灰。
- 尾巴：彗尾，随旋律呼吸。

#### Moony · Spark

- 听歌方式：新声探索者。
- 耳型：一高一低的不对称搜索耳。
- 本色：琥珀与暖黄。
- 尾巴：无。

#### Moony · Chorus

- 听歌方式：跟唱共鸣者。
- 耳型：向外展开的声场扇耳。
- 本色：珊瑚粉与玫红。
- 尾巴：卷尾，随副歌打拍。

#### Moony · Hush

- 听歌方式：安静陪伴者。
- 耳型：贴近圆面的短包耳。
- 本色：鼠尾草绿与灰绿。
- 尾巴：无。

## 6. 客户端接入架构

### 6.1 冻结加载边界

以下现有契约保持不变：

- `window.__ModuleLoader__.load(...)` 入口。
- `factory(require)` 与 `apply(ctx)` 签名。
- `exports.inject = ["slots"]`。
- `@deepseek-ai/dsh-client-ui-slots` 客户端注入声明。
- `sidebar.footer.action` 中的现有开关注册。
- 服务端路由、工具和 `cordis.patch.yml`。

本阶段不增加静态 import、动态 import、新客户端依赖或设置页 injection，以降低模块加载风险。

### 6.2 内部单元

代码仍由现有 `client.js` 入口加载，但在入口内部形成三个独立单元：

1. `MOONY_CATALOG`
   - 保存七个角色的纯数据定义。
   - 每个角色包含稳定 ID、显示名、副名、耳型、颜色变量、尾型和待机动作标识。
   - 不包含可执行 CSS 或动态代码字符串。

2. `resolveMoonyState`
   - 校验角色 ID 和字段。
   - 把播放内容与 agent 状态归一化为有限状态。
   - 未知值一律回退到 `Moony Classic` 或 `idle`。

3. `MoonyPet`
   - 只渲染圆脸、左右耳、耳尖灯、可选尾巴与媒体内容。
   - 不负责轮询、播放器控制、歌词解析、拖动或 slot 注册。
   - 通过稳定 class 和 `data-*` 属性选择角色与状态，不拼接任意 CSS。

这些单元可通过现有模块导出供测试使用，但不会改变宿主调用入口。

### 6.3 角色选择

- 选择器位于现有展开音乐浮窗内。
- 选择后立即更新 React state，折叠态宠物随之重渲染。
- 使用新版本化 localStorage 键保存角色 ID，例如 `dsh-moony-singer:pet-id:v1`。
- 默认 ID 为 `classic`。
- 旧测试版本留下的 `moony-pet` 等键不直接信任；无法映射时回退 `classic`。
- localStorage 读写失败不影响本次会话选择。

## 7. 数据流

1. 现有 `/dsh-alger/state` 轮询继续产生播放状态、媒体信息与 agent 状态。
2. 音乐播放器组件读取当前角色 ID。
3. `resolveMoonyState` 产生：
   - 已校验角色定义。
   - `idle | running | waiting | failed | review` 状态。
   - `blank | media` 圆脸模式。
   - 可用媒体 URL 或 `null`。
4. `MoonyPet` 根据结果渲染稳定 DOM 层。
5. CSS 变量提供角色本色；状态 class 只控制信号色和动作。
6. 媒体图片触发 `onError` 时切换为空白脸，不修改播放器状态。

## 8. DOM 与动画分层

为避免多个状态同时争夺同一个 `transform`，使用独立层：

- `pet-shell`：拖动命中与整体位置。
- `pet-rhythm`：播放时的轻微整体律动。
- `pet-tail`：可选尾巴动作。
- `pet-ear-left` / `pet-ear-right`：角色耳型与方向动作。
- `pet-signal`：耳尖灯和轮廓光。
- `pet-face`：空白月面或媒体内容。

状态映射：

| 状态 | 信号色 | 动作 |
| --- | --- | --- |
| `idle` | 熄灭 | 角色自然待机动作 |
| `running` | 蓝 | 双耳交替摆动，约 520ms 一个周期 |
| `waiting` | 橙 | 耳朵向前探听，约 1.4s 一个周期 |
| `failed` | 红 | 短促抖动三次后停止，不使用无限高速循环 |
| `review` | 绿 | 双耳缓慢点头，约 1s 一个周期 |

播放律动位于 `pet-rhythm`，agent 状态动作位于耳朵和尾巴层，两者可以组合而不互相覆盖。

在 `prefers-reduced-motion: reduce` 下关闭持续摆动、漂浮与律动，只保留静态信号色。

## 9. 异常处理与回退

- 未知角色 ID：回退 `Moony Classic`。
- 角色字段缺失：使用 Classic 对应字段补齐。
- 未知 agent 状态：回退 `idle`。
- 无播放媒体：空白圆脸。
- 图片 URL 缺失或加载失败：空白圆脸。
- localStorage 不可用：保持内存状态。
- 单只角色渲染异常：由安全解析结果回退 Classic；不得影响音乐播放器控件。
- CSS 不支持某些高级效果：保留基本圆脸、耳朵剪影与信号色。

## 10. 文件范围

预计实现会修改：

- `client.js`：角色清单、渲染器、选择器、CSS 与回退逻辑。
- `test/moony-series.test.mjs`：新增纯逻辑和结构测试。
- `test/client-slots-injection.test.mjs`：仅在必须验证入口契约时追加断言。
- `demo/overlay.html` 或同等本地演示文件：展示七个角色及 40px/64px 尺寸。
- `docs/IP.md`：写入本设计确认的完整 IP 规范。
- `README.md`：扩展“宠物 IP：月宝 Moony”入口和角色说明。
- `package.json`：仅在发布时更新版本或测试脚本；不得改变现有客户端注入依赖。

不修改 `index.js`、`lib/*`、`cordis.patch.yml` 或 DSH profile。

## 11. 验证策略

### 11.1 自动检查

- 运行现有 `npm run check`。
- 运行现有歌词解析、slot 注入和端到端可运行测试中不依赖真实播放器的部分。
- 验证七个角色 ID 唯一、字段完整、颜色值和枚举合法。
- 验证默认值与无效 ID 均回退 Classic。
- 验证空闲时无 `img`、Emoji 或五官节点。
- 验证媒体存在时只渲染媒体内容，不叠加五官。
- 验证图片错误处理切回空白脸。
- 验证状态信号不修改角色本色 CSS 变量。
- 验证无尾角色不渲染尾巴节点。
- 验证 `exports.inject`、package client inject 和 slot ID 完全保持现状。

### 11.2 可视检查

- 在独立本地演示页同时展示七个角色。
- 每只角色检查 64px 正常尺寸与约 40px 小图标尺寸。
- 检查空白脸、媒体脸和五种 agent 状态。
- 检查边界位置下耳朵、尾巴与歌词气泡不被裁切。
- 检查 `prefers-reduced-motion`。

### 11.3 上线门槛

只有语法、自动测试和独立演示页全部通过后，才允许现有 DSH 加载新版。加载过程使用 DSH 现有受管服务方式，不在 DSH 对话进程内执行自杀式 kill，也不在失败状态下连续自动重启。

## 12. 验收标准

- DSH 可选择 `Moony Classic` 与六只首发角色。
- 刷新页面后有效选择得到保留，无效选择安全回退 Classic。
- 七只角色在不看名字时仍具有不同耳朵剪影，同时明显属于同一系列。
- 空闲圆脸完全无五官；播放内容与空白脸互斥。
- 状态仅改变信号光和动作，不覆盖角色本色。
- 有尾和无尾角色的动作均能清楚传达状态。
- 音乐播放、歌词气泡、拖动、折叠、隐藏和侧边栏恢复入口保持正常。
- 任一角色数据或媒体图片异常不会阻止插件加载，也不会让 DSH 页面失效。
- 现有客户端注入与 slot 契约测试继续通过。
